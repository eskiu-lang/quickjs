# Moving from rquickjs

This package runs the QuickJS that [rquickjs](https://github.com/DelSkayn/rquickjs)
0.6.2 bundles, with the same patches and the same build defines, so a script suite moved
from a Rust host to an Eskiu host sees the same engine: the same syntax support, the same
error messages and stack format, the same number formatting and property order. This
page maps the rquickjs calls an embedder such as Tallgrass's `engine/src/script.rs` makes
to their Eskiu form.

## Calls

| rquickjs | quickjs |
|---|---|
| `Runtime::new()` | `js_runtime()?` |
| `Context::full(&rt)` | `rt.context()?` |
| `ctx.with(\|ctx\| ...)` | not needed: every call takes the context |
| `rt.set_max_stack_size(n)` | `rt.set_max_stack_size(n)` |
| `rt.set_memory_limit(n)` | `rt.set_memory_limit(n)` |
| `rt.set_interrupt_handler(Some(Box::new(f)))` | `rt.set_interrupt(closure)`, or `rt.set_time_limit(ms)` |
| `rt.set_interrupt_handler(None)` | `rt.clear_interrupt()`, `rt.set_time_limit(0)` |
| `rt.set_loader(Resolver, Loader)` | `rt.set_loader(resolve, load)`, or `rt.set_fs_loader(root)` |
| `Module::evaluate(ctx, name, src)` + `promise.finish()` | `ctx.eval_module(name, src)?` (settles the promise) |
| `ctx.eval::<T, _>(src)` | `ctx.eval(src, file)?` and a conversion |
| `ctx.globals().get::<_, Function>("onUpdate")` + `f.call((dt,))` | `ctx.call_global("onUpdate", &dt, 1)?` |
| `if let Ok(f) = globals.get::<_, Function>("onBoot")` | `ctx.call_global_opt("onBoot", null, 0)?` |
| `Object::new(ctx)` | `ctx.object()` |
| `obj.set("k", v)` | `obj.set("k", value)`, `set_num`, `set_str`, `set_bool` |
| `Function::new(ctx, move \|x: f64\| ...)` | `ctx.function(name, length, closure)` or `obj.set_fn(name, length, closure)` |
| argument `Opt<Option<f64>>` | `a.opt_num(i, default)` (undefined and null are missing) |
| argument `Rest<f64>` | `a.rest_nums(i, &list)` |
| argument `Vec<f64>` | `a.numbers(i, &list)` |
| return `Option<String>` (None is undefined) | `c.str(s)` or `c.undefined()` |
| return `Vec<f64>`, `Vec<String>` | `c.num_array(&d[0], n)`, `c.str_array(&list)` |
| `ctx.catch()` + `ex.message()`, `ex.stack()` | the `Result` error text, or `js_last_error()` fields |

## Differences to know

- rquickjs frees a value when its Rust handle is dropped. Here a returned `JsValue` is
  freed with `free()`; `rt.release()` reports any that were missed.
- rquickjs's `Persistent` keeps a value across `ctx.with` calls. Here any `JsValue` can be
  kept as long as the context lives; `dup()` takes an extra reference.
- An exception here is always a `Result` error with message and stack, never the generic
  "Exception generated by QuickJS" that rquickjs gives before `ctx.catch()`.
- Hot reload: as with rquickjs, a module stays loaded in its context. Build a new runtime
  and context from the changed files; releasing the old ones frees everything.

## Checked against Tallgrass

`tools/battle_rules.esk` runs Tallgrass's graphics-free QA scenarios
(`tools/qa-rules` in that repository) through this package, with the same 8 MiB stack, the
same module resolution and the same `engine` stub and `qa` object. It is an optional local
check that needs a Tallgrass checkout, named by `TALLGRASS_DIR`; `eskiuc test` and CI do
not run it.

```bash
eskiuc tools/battle_rules.esk -O2 -o build/battle_rules
export TALLGRASS_DIR=/path/to/tallgrass
build/battle_rules                      # the 8 battle scenarios
build/battle_rules breeding berries     # any others
```

`TALLGRASS_QA_PROJECT` points it at another project than the editor's template.

On Tallgrass commit `5bb43138` the 8 battle scenarios pass with 1777 assertions, the same
count as rquickjs 0.6.2. Over all 74 QA scenarios, the 17 that run without the game engine
pass in both with the same 1866 assertions; the other 57 need the booted game (`game` is
not defined) in both.
